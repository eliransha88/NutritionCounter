# Nutrition Counter

A focused iOS app for tracking daily macronutrient intake — protein, carbs, and fat — in half-serving increments. Built with SwiftUI, Swift Charts, modular static frameworks ([Tuist](https://tuist.io)), and modern Swift concurrency.

---

## Features

### Daily Tracking
- Three counters (Protein, Carbs, Fat) with + / − buttons in 0.5-serving steps
- Value range clamped to 0 – 10 servings per nutrient
- When a nutrient hits its daily goal the counter card **replaces itself with a congratulations state** (animated trophy + green tint) — counters return automatically if you adjust the value back down
- Donut chart summarising today's intake — shows a "No servings logged yet" empty state on a fresh day
- Auto-updating weekday header that rolls over at midnight without requiring an app restart

### Weekly Overview
- Line chart (Swift Charts) plotting all three nutrients across the current week
- Resets automatically at the start of each new ISO week; fills in any missing days on launch

### Settings
- Per-nutrient daily goal, adjustable in 0.5-serving steps (minimum 0.5)
- Goals and logs persist across launches via an App Group `UserDefaults` suite shared with the widget
- Language row that navigates directly to the app's iOS Settings page for system-managed per-app language selection
- App version displayed in the footer for easy support identification

### Home Screen Widget
- **Small** — compact progress rows with colour-coded capsule bars; shows "✓ Done" badge when a goal is reached
- **Medium** — rows with nutrient name, progress bar, and interactive + button; replaces the button with a trophy "Congrats!" label on completion
- **Large** — full cards per nutrient with − and + AppIntent buttons; congratulations banner replaces the controls when a goal is met
- Tapping widget buttons runs `IncrementNutrientIntent` / `DecrementNutrientIntent` via `AppIntents` — no app launch needed
- Widget reloads its timeline automatically when the main app saves data

### Localisation
- Full **English and Hebrew** support
- **Feature modules** (`NutritionCore`, `NutritionUI`, `NutritionHome`): `Localizable.strings` in `en.lproj` / `he.lproj` under each module's `Resources/`. After `tuist generate`, Tuist emits `Derived/Sources/TuistStrings+Nutrition<Name>.swift` with a public `Nutrition<Name>Strings` enum — use it in Swift (e.g. `Text(NutritionHomeStrings.dailyGoals)`).
- **App target**: `NutritionCounter/Resources/Localizable.xcstrings` (app-level strings) and `InfoPlist.xcstrings` for the localised display name
- **Widget extension** (`NutritionAppWidget`): `NutritionAppWidget/Resources/Localizable.xcstrings` for widget-specific copy and intents
- App display name localised: **"Nutrition Counter"** (English) / **"מונה תזונה"** (Hebrew)
- Nutrient abbreviations are derived from the first character of the localised name (no hardcoded letters)
- Switching language is handled at the system level via **Settings → Nutrition Counter → Language**

## Architecture

Modular **static frameworks** wired in `Project.swift` / `Tuist/ProjectDescriptionHelpers`:

| Module | Role |
|--------|------|
| **NutritionCore** | Models, `NutritionStore`, App Group helpers, domain strings |
| **NutritionUI** | Reusable SwiftUI (counters, charts, day header) |
| **NutritionHome** | Main tracker flow, settings sheet, weekly graph composition |
| **NutritionCounter** | Thin app shell (`@main`, root `ContentView`) |
| **NutritionAppWidget** | Widget extension, intents, timeline |

```
NutritionCounter (app)
├── Sources/                       ← ContentView, NutritionCounterApp, …
└── Resources/                     ← Assets, string catalogs, Privacy manifest, Preview Content

Modules/
├── Core/Sources/                  ← store, DailyLog, NutrientType, …
├── Core/Resources/en.lproj|he.lproj/Localizable.strings
├── UI/Sources/                    ← NutrientCounterView, PieChartView, …
├── UI/Resources/en.lproj|he.lproj/Localizable.strings
├── Home/Sources/                  ← DailyTrackerView, SettingsView, …
└── Home/Resources/en.lproj|he.lproj/Localizable.strings

NutritionAppWidget/
├── Sources/                       ← widget, intents, timeline
└── Resources/                     ← Assets, Localizable.xcstrings, Privacy manifest

Derived/Sources/                     ← generated by `tuist generate`
├── TuistBundle+*.swift
└── TuistStrings+Nutrition*.swift  ← NutritionCoreStrings, NutritionUIStrings, …
```

**Key patterns**

| Concern | Solution |
|---------|----------|
| Observable store | `@MainActor @Observable final class NutritionStore` (Core) |
| Widget–app data sharing | App Group `UserDefaults` suite |
| Concurrent widget writes | `WidgetMutationActor` serialises intent-driven `UserDefaults` updates |
| Stale date header | `TimelineView(.periodic)` rolls over at midnight |
| Error / debug logging | `os.Logger` in `NutritionStore` (low overhead in release) |
| Module localisation | `.strings` + `tuist generate` → `Nutrition<Name>Strings` |
| Xcode project | **Tuist** — edit `Project.swift` & helpers, then `tuist generate` |

## Getting Started

```bash
git clone https://github.com/eliransharabi/NutritionCounter.git
cd NutritionCounter
tuist generate
open NutritionCounter.xcworkspace
```

> Open the **`.xcworkspace`**, not the `.xcodeproj`, so Swift Package dependencies resolve correctly.

Before building, ensure the **App Group** `group.com.eliransharabi.NutritionCounter` is registered in your Apple Developer account and linked in Signing & Capabilities for both the **NutritionCounter** app and **NutritionAppWidget** extension targets.

### Test plans

Tuist declares **shared schemes** in `Tuist/ProjectDescriptionHelpers/NutritionCounter+Schemes.swift` (and passes them from `Project.swift`). After **`tuist generate`**, pick the scheme you want in Xcode:

| Scheme | Test plan(s) | Contents |
|--------|----------------|----------|
| **NutritionCounter** (main) | Both plans (Unit is the default; switch in the Test action) | Unit + system targets from the two `.xctestplan` files below |
| **NutritionCounter-Unit** | `TestPlans/NutritionCounter-Unit.xctestplan` only | `NutritionCoreTests`, `NutritionUITests`, `NutritionHomeTests` |
| **NutritionCounter-System** | `TestPlans/NutritionCounter-System.xctestplan` only | `NutritionCoreSystemTests`, `NutritionUISystemTests`, `NutritionHomeSystemTests` |

The per-target schemes Tuist generates by default are still available for individual modules.

After **`tuist generate`**, if target UUIDs change, reopen the test plan in Xcode and re-save if Xcode reports missing targets.

## Localisation

### Modules (Core / UI / Home)

1. Add keys to **`Modules/<Module>/Resources/en.lproj/Localizable.strings`** and **`he.lproj/Localizable.strings`** (same keys in both).
2. Run **`tuist generate`** to refresh **`Derived/Sources/TuistStrings+Nutrition<Name>.swift`**.
3. Use **`Nutrition<Name>Strings.<key>`** in Swift (returns `String`, suitable for `Text(...)`, `Label`, etc.).
4. Do **not** duplicate keys that already exist in a dependency's strings — import the dependency and use its `…Strings` enum.

### App & widget (string catalogs)

1. **`NutritionCounter/Resources/Localizable.xcstrings`** — app-level-only keys (module strings stay in modules).
2. **`NutritionAppWidget/Resources/Localizable.xcstrings`** — widget gallery text, intents, in-widget copy.
3. **`NutritionCounter/Resources/InfoPlist.xcstrings`** — localised `CFBundleDisplayName` / `CFBundleName`.
4. Add new locales in Xcode's string catalog UI and in the project's **Info → Localizations** list.

## Privacy

This app stores all data **locally on-device only** using `UserDefaults`. No data is sent to any server, and no tracking or analytics are collected. A `PrivacyInfo.xcprivacy` manifest is included declaring `UserDefaults` access under reason `CA92.1`.
